# macOS (darwin) runtime requirements.
#
# This is the single source of truth for what the macOS build needs at runtime:
# both scripts/build_macos_arm.sh and the CI macOS job install from this file,
# so the list cannot drift away from what the code actually imports. Keep it
# minimal so `pip install -r requirements/darwin.txt` works on Apple Silicon
# without falling back to GitHub.
appdirs
cherrypy
lxml
requests
rumps
netifaces
# macast/macast.py imports pyperclip directly. rumps happens to depend on it,
# but relying on that transitive dependency is how this list silently drifted
# from what the code imports in the first place.
pyperclip
# Same story one level down: macast/utils.py imports AppKit at module level (on
# darwin), and plugins/screen_mirror.py imports Foundation and objc for the
# CoreAudio aggregate-device calls. Both come from this framework, which rumps
# pulls in as pyobjc-framework-Cocoa -- declared here rather than inherited, so
# dropping rumps cannot silently take the audio bridge with it.
pyobjc-framework-Cocoa
# The screen-mirror plugin's ScreenCaptureKit capture path (macOS 13+), which
# replaced the avfoundation + BlackHole rig as the default grab. These are
# imported lazily inside screen_mirror.py -- a machine without them falls back
# to avfoundation, so a missing entry here degrades silently instead of
# crashing. That is exactly why they are declared: a *shipped* .app must carry
# them, or users never see the ~450 ms-faster path. ScreenCaptureKit already
# depends on CoreMedia; both are named rather than inherited (same principle
# as pyobjc-framework-Cocoa above).
pyobjc-framework-ScreenCaptureKit
pyobjc-framework-CoreMedia
# Required by macast/discovery.py (mDNS advertisement for Chromecast/AirPlay).
# Missing it is not a graceful degradation: the module import fails and the
# app does not start at all.
zeroconf
# The screen-mirror plugin's WebRTC output shape (「浏览器 · WebRTC」). Both are
# imported lazily inside screen_mirror.py -- a machine without them keeps every
# other mirror target and this one refuses with the two ways to get it. Since P9
# this file names them for SOURCE RUNS ONLY: the macOS job does not pip-install
# them and setup_py2app.py does not carry them, because `av` alone is forty-some
# MB behind a target a minority uses. A downloaded .app gets them by pressing
# 「一键安装 WebRTC 依赖」 on the 电脑投屏 page, which fetches the matching
# Macast-WebRTC-extras-*.zip release asset (see the header of build.yml and
# macast/plugin_repo.py). This file is still the source of truth the macOS build
# and the CI job read for everything else -- which is why the entry stays: it is
# what puts aiortc under the plugin import allowlist (Part 30) and lets a
# from-source run exercise the target at all.
aiortc
av
